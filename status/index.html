System status

This page runs a real health check against the LocalBoost API when the API is connected to this website. When it is not connected, it says so. It shows no uptime percentage and claims no monitoring we do not run.

Last updated 30 October 2026

Checking...

What this check does

When the API is connected, your browser sends one request to the API's /health address and shows exactly what came back: the HTTP status, the service name, whether the database check passed, how long the round trip took from your device and the time of the check. The result is for this moment and this browser only. It is not a record of the past.

What this page does not do

  • It does not show an uptime percentage or a history of incidents, because we do not run continuous monitoring or keep that history yet.
  • It does not check Google, Razorpay or any other provider. If one of them has a problem, this page will not know.
  • It does not prove that every feature works. The health check confirms the API answered and could run a trivial database query. Individual features can still fail.

If something looks wrong

Check this page, then the help center and troubleshooting guide. If the problem remains, send a bug report or email support@localboost.in with the page address, the time and what you saw. Please include the request identifier if an error message shows one.

How the check was designed

The request uses no cookies and sends no personal data. It asks the browser not to use a cached answer, gives up after eight seconds and treats anything other than a readable, successful answer as a failed check rather than guessing. If a browser extension, a firewall or a cross-origin setting blocks the request, you will see "could not be reached", and this page cannot tell those causes apart from a real outage.

Future plans

We intend to add independent monitoring and a published incident history once the production API is running. Until it exists, we will not describe it. When it does, the changelog will say so.
