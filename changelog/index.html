Changelog

Changelog

What has been built, changed and fixed, with dates. LocalBoost has no version numbers yet, so entries are grouped by the date of the commit in the project history.

How to read this page

Each entry comes from the repository's commit history. Dates are commit dates. There are no release numbers because nothing has been released as a versioned product. A line under Added means the code exists and has been tested locally. It does not mean the feature is live for customers: the production API, Google approval, a rank-data provider and payment approval are still outstanding. The features and help center pages state the status of each area.

30 October 2026

Added

  • Google sign-in callback with encrypted refresh tokens, hashed sessions, logout and discovery of Business Profile locations.
  • Waitlist funnel: the audit result links to a waitlist form, a waitlist API and waitlist pages.
  • Backend scaffold: module router, route and job registry, Origin check, database migrations and the written API contract.
  • Continuous integration and deploy workflows, site integrity scripts, a 404 page and security headers.
  • Razorpay billing: orders, payment signature verification, signed webhooks, GST invoices and plan expiry.
  • Local rank-tracking engine: grid scans through a provider adapter, history, schedules and CSV export. No rank-data provider is connected.
  • Google integrations: token refresh, review fetch and confirmed replies, performance metrics, Search Console with an incremental read-only permission, and disconnect.
  • Unified audit engine with a documented scoring model, evidence-based findings, audit comparison, a 30-day plan and CSV export.
  • Platform module: business update and archive, account data export, consent-gated first-party analytics, admin metrics and retention jobs.
  • SSRF-safe website crawler with robots.txt and sitemap handling, and a PageSpeed Insights proxy.
  • Design system with light and dark tokens, brand assets and a style guide; drafted legal pages including a refund policy and a data-retention page; Hindi page titles.

Changed

  • Phase 1 SEO foundation: self-canonical Hindi pages, reciprocal hreflang, sitemap and robots.txt on the www host, duplicate social tags removed.
  • Mobile layout fixed site-wide with shared responsive CSS, a hamburger menu, a compact cookie banner, favicon and social preview tags.
  • Generic and misleading FAQs replaced with accurate ones; demo data, a fake connected state, a simulated payment and placeholder ads removed.
  • Security hardening: the rate limiter now fails closed, requests carry identifiers, request bodies are size-limited, and security tests were added.

Fixed

  • Syntax errors in the Worker code.
  • Fake contact promises removed from pages.
  • Site search, which was completely broken, and a script error on the reports page.
  • Places lookup honesty fix in the free tool and several tool pages.
  • A leftover AdSense comment removed from the about page.

1 October 2026

Changed

  • Review workflow hardening was tracked for the first time in the project history.

Where the project stands

The site, the free tools, the Hindi pages and the design system are built and checked locally for broken links, canonical tags and mobile layout. The backend is a set of modules with automated tests, written to run on Cloudflare Workers with a SQLite-compatible database. It has not been deployed, and no module has run against live Google or payment accounts. That is the honest state, and each entry in this list should be read with it in mind. As soon as an item goes live for customers, we will say so here with the date.

In progress and not yet in the history

These backend modules exist in the working copy at the time of writing but are not yet part of the committed history, so they are not dated above: team workspaces with roles and invitations, notifications and an email outbox, Action Center tasks, stored report snapshots with expiring share links, an evidence-based assistant, review analytics, and competitor lookup through the official Google Places API. Their status will move into the dated list once committed. The public pages you are reading (features, help center, status, security, cookie policy, bug report and the shared report viewer) are new too.

What is not here

We do not list customer counts, uptime figures or performance gains, because we have none to report. If you spot something on a page that looks wrong, tell us through the bug report form.
